Data-Efficient Scientific Pretraining

Scientific data is hard to grow. Across molecules, DNA, and crystals, one training recipe makes a fixed dataset go much further.

November 2026

TL;DR

  • We train on fixed datasets of molecules, eukaryotic DNA, and crystal structures. The same two ideas carry across all three: reuse model blocks and average snapshots saved during training.
  • One run matches what a tuned single pass would need 5.4–6.2× more unique data to achieve for molecules, 5.5–8.9× for DNA, and 7.4–13.3× for crystals where we can measure the full multiplier. Simply repeating the data yields smaller gains.
  • Against published training recipes run on the same data, our recipe needs about 20× less data for DNA and crystals. For molecules, 85M unique tokens reach the loss of Xu et al.'s best released model, which was trained on 4.4B tokens.
  • The gains also show up beyond pretraining: in molecular and materials property prediction, gene annotation, clinical variant effects, and crystal structure prediction.

1Why Repeat Scientific Data?

Training compute keeps getting cheaper. New scientific data does not. A crystal structure requires a calculation or an experiment. The informative parts of a genome are finite: OpenGenome2's curated set of eukaryotic genic windows contains 0.42 trillion bases, with much less available for most lineages. When a dataset is hard to expand, we need to learn more from each example already in it.

Repeating data helps, but the details matter. For web text, Muennighoff et al. found that the first few extra passes are nearly as useful as new data; later passes add less. Our work on protein language models (Baron et al.) found larger gains with a carefully tuned training setup. q0 developed training methods for making many passes over a fixed dataset.

We wanted to know whether those methods work across scientific data with very different forms. We chose molecular SMILES strings, eukaryotic DNA windows, and crystal structures written as CIF files. Their vocabularies range from 8 tokens for DNA to 591 for molecules; their documents and prediction tasks differ just as much.

For each domain, we compare our recipe with a tuned single pass, tuned plain repetition, and a published training recipe. We also test whether better pretraining helps on downstream tasks.

2How We Tested the Recipe

2.1Putting Gains in Units of Data

Our main measure asks a simple question: how much unique data would a strong single-pass model need to match this result? If our method trains on 25M unique tokens and earns a 10× data multiplier, a single pass would need 250M tokens to reach the same held-out loss.

We first tune a single-pass baseline over model size, learning rate, and batch size at several data budgets. Let $L_s(U)$ be its best held-out loss after one pass over $U$ unique tokens. If another method reaches loss $L(U)$ using that same $U$, its data multiplier is

$$m(U) = \frac{L_s^{-1}\big(L(U)\big)}{U},$$
(1)

We estimate the matching single-pass budget by interpolating between measured points on that baseline, with score or loss linear in the logarithm of unique tokens. If a result exceeds the measured baseline, we extend its final segment to estimate the matching budget. These extrapolated multipliers depend on the baseline's final slope and are marked † throughout. We calculate downstream multipliers the same way, using downstream scores.

All scores use held-out data. We test on unseen molecules, OpenGenome2's held-out DNA split, and crystal structures with training-set duplicates removed. For DNA, we make every model choice on a separate set of held-out genera.

2.2The Recipe

The recipe builds on q0 and Chen et al. Figure 1 shows the shared core. Two components appear in every domain:

Snapshot ensembling. We divide training into 64 cycles and save the model at the end of each one. Within a cycle, the learning rate falls from its peak to $0.08\times$ while weight decay rises from $0.7\times$ to $1\times$. At prediction time, we average the saved models' next-token probabilities:

$$p_{\text{ens}}(x_t \mid x_{<t}) = \frac{1}{K}\sum_{k=1}^{K} p_{\theta_k}(x_t \mid x_{<t}).$$
(2)

Looped depth. The model has an opening block, a core whose weights are reused, and a closing block. We run the core three times for molecules and crystals, and twice for DNA. At each loop boundary, the operator from Chen et al. normalises the state and adds back a learned projection of the opening block's output.

We also tested two additions in every domain, keeping them where they helped. Chain distillation asks each new cycle to learn from both the data and the previous snapshot's predictions: $\mathcal{L} = (1-\alpha)\,\mathrm{CE} + \alpha\,T^2\,\mathrm{KL}\big(p^{(T)}_{\theta_{k-1}} \,\|\, p^{(T)}_{\theta}\big)$. Weight perturbation gives the model a small random push after each snapshot, $\sigma\,\mathrm{std}(\theta)\,z$, so the next cycle starts from a different point.

2.3What Changes Between Experiments

We keep the cycle shape and 64 snapshots fixed across domains. Each domain has a preset loop count: three for molecules and crystals, two for DNA. For each domain and data budget, we tune model size, number of passes, peak learning rate, and weight decay. Appendix C gives the settings.

3Three Very Different Datasets

The three domains differ in their source data, held-out tests, downstream tasks, and published baselines (Table 2). We train decoder-only transformers from scratch in each one. Documents stay intact during packing, so we can count unique training tokens exactly. Appendix C describes the shared optimiser and training setup.

4How Much More Does the Data Teach?

Across all three domains, one run of the recipe reaches a lower held-out loss than both a tuned single pass and tuned plain repetition (Figure 2). The gain is consistent across data budgets:

  • Molecules: 5.4–6.2× the unique data of a single pass at every budget from 5M to 200M tokens.
  • DNA: 5.5–8.9× on the held-out split. The gain rises through 20M tokens, then stays near 8–9×.
  • Crystals: 7.4–13.3× from 5M to 50M tokens. At 100M and 200M, the recipe beats a single pass over the entire available corpus. Extending the baseline gives estimated multipliers of 8.2×† and 5.8×†.

Figure 3 makes the pattern easier to see. As datasets grow, plain repetition becomes less valuable in every domain. The recipe keeps its advantage or improves on it.

The size of the multiplier also depends on how quickly a single pass improves with more data. For crystals, doubling the data cuts loss by only 0.014–0.025 nats. The recipe's roughly 0.055–0.065-nat gain is therefore worth several doublings. The DNA baseline behaves differently: it stays nearly flat until about 50M tokens, then improves sharply.

These results use one training run per budget. Combining several runs can improve them further, at extra compute cost (Appendix B).

5How Does It Compare With Published Models?

We also compare against a published model or training recipe in each domain. That comparison reflects both the strength of our single-pass baseline and the benefit of repeated training. Table 4 shows both pieces so readers can see where the gain comes from.

DNA. We train a parameter-matched, scaled-down Evo 2 for one pass using Evo 2's recipe: AdamW, warmup, and cosine decay. Its loss changes little until about 300M tokens, and its single pass is worth 0.2–1.7× ours.

On the Evo 2 curve, one run of our recipe needs 18–24× less data across the 5M–200M budgets. At 100M unique tokens, it matches the loss Evo 2's recipe reaches with 2B. The plateau comes from both the optimiser and the architecture: with our recipe, the scaled-down Evo 2 performs as well as our transformer.

Crystals. We tune CrystaLLM's one-pass recipe at each budget. Its result is worth 0.3–0.6× our tuned single pass. Measured against the CrystaLLM curve, our recipe is worth 21–24× at 5M–25M. From 50M onward, it even beats CrystaLLM's one-pass result on the whole corpus. We use newly trained CrystaLLM baselines because the released checkpoints saw data from the held-out split.

Molecules. Xu et al. released single-pass checkpoints trained on up to 4.4B tokens. Our tuned single pass matches their best model's loss with about 9× less data. The repeated-data recipe cuts that requirement by another 5.7×, reaching the same loss with about 85M unique tokens. In property prediction, the recipe overtakes Xu et al.'s best model from 100M unique tokens.

6Does Better Pretraining Carry Over?

A lower pretraining loss is useful if it helps with real tasks. We evaluate transfer in two ways: by fine-tuning small adapters for a task, and by using the pretrained model directly in zero-shot tests.

6.1Fine-tuning

For property prediction and gene annotation, we keep the pretrained network frozen and train small LoRA adapters. This lets us compare how well the representations learned during pretraining support each task (Figure 4).

  • Molecules: We pool eight MoleculeNet tasks with scaffold splits into one score, scaled to $\ln U$ on the single-pass curve. With 50M unique pretraining tokens, the recipe fine-tunes better than a model trained once on 3B tokens.
  • DNA: We label each base as intergenic, intronic, exonic, or coding across six held-out genera. At 5M–20M tokens, the recipe's averaged fine-tuned snapshots are worth 8.2–10.7× as much unique data. From 50M onward, they beat a single pass over 2B tokens.
  • Crystals: We predict perovskite formation energy and shear and bulk moduli on three Matbench tasks. One fine-tuned recipe snapshot is worth 11.1× at 5M tokens and 7.0× at 10M. From 25M onward, it matches or beats a single pass over the whole corpus.

6.2Zero-shot Evaluation

These tests use the pretrained models without any task-specific training (Figure 5 and Table 5).

DNA. We score human ClinVar variants using the model's relative likelihood of the alternative and reference sequences. Models trained with our recipe on 50M–200M unique tokens match single-pass models trained on 13–14× more data. Humans are absent from our training set, and across models the ClinVar score tracks pretraining loss.

Crystals. We give the model a composition and ask it to generate a structure. At 5M–50M unique tokens, the recipe matches the true structure as often as a single pass trained on 4.9–10.5× more data, or CrystaLLM's recipe trained on 15–24× more.

7Which Parts Matter?

To see what drives the gain, we remove one component at a time and rerun the best configuration at each budget. For the comparison without ensembling, we use the best single snapshot from the full run (Figure 6).

  • Averaging snapshots helps in every domain. For molecules, the best single snapshot is worth 3.2–4.1× the data, while the ensemble reaches 5.4–6.2×. At 5M–50M crystal tokens, those ranges are 5.0–9.9× and 7.4–13.3×. For DNA, averaging adds about 1–2× at most budgets; at 10M, the difference is within seed noise.
  • Reusing the core blocks helps more as the dataset grows. Removing looping costs 0.45× at 5M molecular tokens and 1.33× at 200M. For DNA, the cost grows from 0.9× at 20M to 3.4× at 200M. Looping also helps at every crystal budget we tested, by 0.8–2.3×.
  • The additions depend on the domain. Chain distillation adds 0.4–0.6× for molecules at 50M tokens and below. It adds little for DNA; adding it to the crystal recipe did not help.

8What We Learned

Molecules, DNA, and crystals look very different to a language model. Yet the same core recipe—looped depth and an ensemble of training snapshots—helps in all three. One run performs like a single pass with roughly five to thirteen times as much unique data. The advantage carries into every downstream task we measured.

Against the published recipes for DNA and crystals, our recipe reaches the same loss with about twenty times less data. We do not yet know how far the gain continues beyond 200M unique tokens; at large budgets, our comparisons sometimes exceed the longest measured single pass.

We also want to understand why looping matters more as the dataset grows. Chen et al. find that looping regularises multi-epoch training and becomes compute-optimal as models grow, which suggests testing more loops at larger budgets. Future posts in this series will test how broadly the recipe transfers.

9Where These Ideas Come From

Training with limited data. Muennighoff et al. describe how gains change as training data is repeated. For protein models, Baron et al. show how Muon and strong weight decay improve multi-epoch training, and propose snapshot ensembling and chain distillation as next steps.

Parts of the recipe. Snapshot ensembles (Huang et al.) collect several models from one run using a cyclic schedule (Loshchilov and Hutter). Training a model from an earlier model's predictions builds on Hinton et al. and Furlanello et al.. q0 brings these ideas together for repeated-data pretraining. Reusing blocks across model depth dates to the Universal Transformer (Dehghani et al.); Chen et al. introduce the loop-boundary operator used here.

Scientific models and tasks. Xu et al. study SMILES language models. Evo 2 (Brixi et al.) uses OpenGenome2, the source of our DNA data. CrystaLLM (Antunes et al.) generates crystal structures as CIF text. The downstream evaluations draw on MoleculeNet (Wu et al.), Matbench (Dunn et al.), and ClinVar (Landrum et al.).

Appendix

AFull Pretraining Results

BWhat More Compute Can Buy

The main results use one run per data budget. With more compute, we can train several runs on the same data and combine their predictions. Snapshots within one run tend to be similar. Separate runs can make different errors because they use different seeds, weight decays, model shapes, pass counts, or recipe components. Combining them can take advantage of those differences.

Adaptive mixture. We include every second snapshot for DNA and every fourth for crystals from every run at a budget. Each included model is a member $j$ with prediction $p_j$. The mixture predicts $p(x_t) = \sum_j w_{t,j}\, p_j(x_t \mid x_{<t})$. We initialise the weights from a prior $\pi$ fitted with EM, then update them after each token in a document:

$$w_{t+1,j} = (1-\alpha)\,\frac{w_{t,j}\,p_j(x_t \mid x_{<t})^{\beta}}{\sum_i w_{t,i}\,p_i(x_t \mid x_{<t})^{\beta}} + \alpha\,\pi_j,$$
(B1)

A member gains weight when it predicts the current document well; $\alpha$ keeps some weight near the prior. We fit the prior and $(\beta, \alpha)$ on data that we do not use for scoring. For DNA, that is the validation genera. For crystals, we fit on one half of the held-out CIFs and score on the other, then reverse the halves. Setting $\beta = 0$ gives a weighted ensemble with fixed weights.

DNA. Mixing 8–11 runs raises the multiplier from 5.5–8.9× for one run to 10.0–14.0×. On the Evo 2 curve, the mixture is worth 25–31×. Adapting weights within each document supplies much of the gain: fixed weights reach only 8.7–10.4×. At 5M–20M, even three seeds of one recipe variant reach 8.4–10.4×. From 50M onward, mixtures of looped runs do better than mixtures without looping.

Crystals. The mixture adds 0.7–1.4× at 5M–25M and no measurable gain at 50M, despite combining 28–91 runs. Most runs have the same tuned model shape and make similar errors. On CrystaLLM's curve, the crystal mixture is worth 24.5–25.7× at 5M–25M. We have not run this cross-fitted mixture for molecules.

Compute cost. Training a mixture costs the sum of its runs, and prediction evaluates every member on every token. Extra runs help less once their errors become similar. When spending more compute, runs with different seeds, weight decays, shapes, or recipe components are more useful than repeats of the same configuration.

CTraining Details

We carry the same cycle shape and 64 snapshots from molecules to the other domains. The loop count is preset for each domain. In each cycle, learning rate falls from its peak to $0.08\times$ while weight decay rises from $0.7\times$ to $1\times$. For each domain and budget, we tune model size, number of passes, peak learning rate, and weight decay. The product of learning rate and weight decay matters most. If it is too small, snapshots memorise the training data; the best value falls as the budget grows.

  • Molecules. An 85M model (12 layers, width 768) for 128 passes, all of them in 64 two-pass cycles. Peak Muon learning rate 0.02 for $U \le 50$M and 0.01 above (AdamW 0.002 for embeddings and the head); batch 16k tokens for $U \le 20$M and 65k above. Weight decay follows $\mathrm{lr}\cdot\mathrm{wd}\cdot(\text{steps per pass}) \approx 1.22$, a weight-decay timescale of about 0.82 passes at every budget. Chain distillation from cycle 9 ($\alpha = 0.45$, $T = 1.2$) with weight perturbation ($\sigma$ from 0.25 to 0.05).
  • DNA. A flat learning-rate phase over the first half of training, then 64 cycles; the ensemble is the best prefix of snapshots, chosen on validation. The recipe was assembled one component at a time at 5M and 10M on a 25M model, then carried to larger budgets on an 85M model with a short learning-rate × weight-decay bracket per budget. Core looped twice; chain distillation from cycle 32 ($\alpha = 0.2$ at 5M, 0.7 above). Weight perturbation and distillation from the running ensemble gave nothing.
  • Crystals. A 113M model (1 prelude, 10 core blocks applied three times, 1 coda; about 300M executed parameters per token), batch 16 rows of 1,024 tokens, a flat phase over the first half then 64 cycles, weight perturbation after each snapshot. The number of passes (8–192), learning rate and weight decay were tuned per budget, 52–224 runs per budget. The optimal product of learning rate and weight decay falls from $2\cdot10^{-3}$ at 5M to $3\cdot10^{-5}$ at 200M, and at 5M–10M half the optimum lets the snapshots memorise. Precycle fraction, cycle floors, snapshot count, loop count and perturbation size, each varied once around the defaults, moved the loss by less than 0.0005 except a larger perturbation, which hurt.

All models are decoder-only transformers trained from scratch. We use Muon for matrix parameters and AdamW for embeddings and the output head, without warmup or dropout. We pack whole documents with a document mask, which lets us count unique training tokens $U$ exactly.
